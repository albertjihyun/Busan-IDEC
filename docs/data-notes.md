## AdVitam Exp4 (외부 검증 데이터)

조사 시점에는 주 학습 데이터로 잡고 있었으나, 라벨 간격을 확인한 뒤 **외부 검증용으로 역할을 바꿨다**(아래 「라벨 시간 해상도 비교」 참조).

Zenodo 레코드 7319612 (concept DOI 10.5281/zenodo.7214953). 6개 실험 중 **Exp4가 수면부족 조작 실험**이라 이것만 받는다. 전체는 13.9GB, Exp4.zip만 3.97GB(압축 해제 시 약 11GB).

실험 설계: 63명, 고정형 운전 시뮬레이터, 조건부 자동운전(L3). 절반은 수면부족(6시간 미만), 나머지는 7시간 이상. 시골/도시 시나리오를 각 30분씩, 순서는 균형. 실험 시각(오전 10시/오후 4시)도 통제.

### 피험자 코드

`01_AC16` 형식으로, 코드 자체에 조건이 들어 있다.

| 자리 | 의미 |
|---|---|
| `01` | 피험자 번호 (01~63) |
| `A` / `D` | Alert(수면 정상) / Drowsy(수면부족) |
| `C` / `U` | 시골 먼저 / 도시 먼저 |
| `10` / `16` | 실험 시각 (오전 10시 / 오후 4시) |

### 원본 생체신호 — `Raw/Physio/Txt/<code>.txt`

BioPac MP36, **1000 Hz**, 탭 구분. 앞 11행이 메타데이터이고 12행부터 데이터다.

```
C:\DrivingExp4\BioPac_Data\1_AC16.acq
1.000000 msec/sample
3 channels
EDA (0 - 35 Hz)        microsiemens     → CH1
ECG (.5 - 35 Hz)       mV               → CH2
Respiration            mV               → CH3
min  CH1  CH2  CH3                      ← 열 이름 (12행 근처)
     4726500 4726500 4726500            ← 채널별 샘플 수
0    1.43127  -6.45111  8.78601          ← 데이터 시작
```

- **1열은 경과 시간인데 단위가 분(minute)이다.** 샘플 간격이 1.66667e-05 분(= 1 ms)으로 찍힌다. 마커 파일은 초 단위라서 단위를 맞춰야 한다.
- 우리가 쓸 신호는 **CH2(ECG, mV)** 하나다. EDA·RESP는 쓰지 않는다.
- 한 명당 약 472만 샘플(약 79분), 파일 1개가 177MB. 63명이면 11GB이므로 **전부 풀어두지 않고 피험자 단위로 열어 RR만 뽑고 원본은 버리는 방식**으로 처리한다.
- 같은 신호가 `Raw/Physio/BioPac/<code>.acq`(BioPac 전용 포맷, 28MB)로도 있지만 txt로 충분하다.
- **샘플링 주파수는 1열에서 역산하지 말고 헤더의 `1.000000 msec/sample`을 쓴다.** 1열이 유효숫자 6자리 지수 표기(`1.66667E-005`)라 차분 중앙값을 내면 1.02 ms(980 Hz)로 나온다. 실제는 1000 Hz다.

**포맷 검증** (01_AC16, 앞 60초, neurokit2 0.2.13): R피크 71개 → 71.7 bpm, RR 평균 837 ms(범위 747~908), SDNN 38.4 ms, RMSSD 25.7 ms. 안정 상태 성인으로 타당한 값이라 열 순서와 단위 해석이 맞다고 본다.

### 구간 마커 — `Raw/Physio/Txt/<code>-markers.txt`

```
Event 1:  140.9850   Baseline Start, 16:05:53
Event 2:  468.7300   Baseline End, 16:11:21
Event 3:  669.5600   Training Start, ...
Event 5:  1080.9250  Block1 Start, ...
Event 8:  4683.9250  Block2 End, ...
```

**초 단위**다. Baseline(5분) / Training(5분) / Block1 / Block2(각 30분)로 구간이 나뉜다. 학습에 쓸 구간은 Block1·Block2이고, Baseline은 개인차 보정용 기준값으로 쓸 수 있다.

### 라벨 — `Preprocessed/Questionnaire/Exp4_Database.csv`

63행 × 126열. 졸음 라벨 후보는 두 종류다.

1. **수면부족 조건** (`sleep_condition`, 피험자 코드의 A/D와 동일): 32명 vs 31명. 피험자 단위 라벨이라 시간에 따라 변하지 않는다.
2. **KSS 자기보고** (1~9 척도, 값 10이 1건 있음):

   | 열 | 시점 | 분포 (n=63) |
   |---|---|---|
   | `KSS_0` | 실험 시작 전 | 1~8, 중앙값 5 근처 |
   | `KSS_1` | Block1 직후 | 2~9, 4와 7에 몰림 |
   | `KSS_2` | Block2 직후 | 3~10, 6에 몰림 |

   `KSS_Countryside`, `KSS_Urban`은 값이 음수까지 나오는 것으로 보아 **절대값이 아니라 변화량**이다. 절대 KSS가 필요하면 `KSS_0/1/2`를 쓴다.

**주의: KSS는 실험 중 3번만 측정됐다.** 30분 블록 안의 매 윈도우에 붙는 연속 라벨이 아니다. 따라서 2단계 라벨링은 "블록 직후 KSS를 그 블록의 모든 윈도우에 부여"하는 방식이 되고, 이건 블록 후반부에 유리하고 초반부에 불리한 근사다. 임계값(예: KSS ≥ 7)과 함께 이 근사의 한계를 성능 보고서에 적는다.

### 참고용 전처리 특징 — `Preprocessed/Physio/windows/`

Neurokit으로 계산해 둔 윈도우 단위 특징이다. 우리 파이프라인의 **검증 기준선**으로 쓴다(같은 신호에서 우리 값이 비슷하게 나오는지 확인).

`features_window_180s_overlap_50.csv` 기준: 1,859행 × 404열, 60명(3명 제외됨), Rural 1,020 / Urban 839 윈도우, `label_sleep` 0/1이 899 : 960으로 거의 균형. 한 명당 32윈도우.

- 메타 열: `subject_id`, `label_sleep`, `label_first_scenario`, `label_time_exp`, `period`, `segment_id`, `time_start`, `time_end`
- 우리가 쓸 4종이 그대로 있다: `HRV_MeanNN`, `HRV_SDNN`, `HRV_RMSSD`, `HRV_pNN50`
- 접미사 `_Bl`(베이스라인) / `_Dr`(해당 구간) / `_Dr-Bl`(차분)
- `HRV_MeanNN_Dr` 결측 0건
- 윈도우 길이는 180/360/720초, 겹침 0/25/50%만 제공된다. **계획서의 60초 윈도우는 여기 없으므로 원본에서 직접 만들어야 한다.**

### 기타

- `Raw/Sleep/Fitbit_Data.csv`: 실제 수면 시간(`6h27` 형식). 결측(`-`)이 있다.
- `Preprocessed/PVT/`: 5분마다 표적에 반응한 시간. 졸음의 객관 지표라 KSS 보조 라벨로 검토할 만하다.
- `Preprocessed/Questionnaire/Exp4_Documentation.xlsx`: 변수 코딩과 **분석에서 제외할 피험자 목록**이 들어 있다. 2단계 전에 확인한다.

## 라벨 시간 해상도 비교 (2026-09-07 조사)

"졸음 판정은 실시간인데 라벨이 30분마다면 맞는가"라는 문제 때문에 후보 데이터셋의 **라벨 간격**을 다시 확인했다.

먼저 구분할 것: **판정 주기와 라벨 해상도는 다른 문제다.** 칩이 몇 초마다 판정할지는 우리가 정하는 값(60초 창을 30초마다 갱신)이고 데이터와 무관하다. HRV 특징은 RR을 수십 개 모아야 계산되므로 어차피 수십 초 단위이며, 즉각 반응이 필요한 고개 떨굼은 IMU 규칙이 맡는다(학습 데이터가 필요 없다). 라벨 해상도는 **학습과 평가할 때만** 문제가 된다. 30분 블록 전체에 같은 정답을 붙이면 블록 초반의 각성 구간까지 졸음으로 학습되고, 정확도 수치도 그만큼 부정확해진다.

| 데이터셋 | 인원 | 신호 | 라벨 | 라벨 간격 | 접근 |
|---|---|---|---|---|---|
| AdVitam Exp4 | 63 | ECG 1000Hz | KSS 자기보고 | **30분** (블록당 1회) | Zenodo 공개 |
| AdVitam Exp4 (PVT) | 63 | 〃 | 반응시간(객관) | **약 5분** | 〃 |
| MPD-DF | 50 | ECG 1024Hz + EEG | 의사 주석 5단계 | **30초 에폭** | figshare, CC BY 4.0, 12.2GB |
| DD-DB | 10 | ECG 128Hz | 본인 버튼(졸릴 때) | 이벤트 시각 | Dryad |
| UL-DD | 19 | 심박·EDA·SpO2 | KSS | 4분 | 저자 요청 필요 |
| PPG-DaLiA | 15 | PPG + ECG | 졸음 라벨 없음 | — | UCI 공개 |

확인한 내용:

- **AdVitam에는 5분 간격 지표가 있다.** PVT(5분마다 화면의 표적에 버튼으로 반응)의 반응시간이 시나리오당 5개씩 기록돼 있다(`RT_0`~`RT_4`). 원본 주행 로그에서 실제 간격을 확인하니 487.7초와 790.1초로 302초(약 5분)였다. 반응시간은 각성도의 객관 지표라 KSS(30분)보다 촘촘한 보조 라벨로 쓸 수 있다.
- **MPD-DF의 라벨이 가장 촘촘하다.** 수면센터 의사가 EEG 주파수 특성을 보고 **30초 에폭 단위**로 각성/피로1/피로2/N1·N2의 5단계를 주석했고, 이진(각성 vs 피로)으로도 쓸 수 있다. 계획서에는 교차 검증용(선택)으로 적었지만 라벨 해상도만 보면 주 학습에 가장 적합하다. 다만 라벨 정의가 **뇌파 기준**이라 KSS 자기보고와 같은 것을 재는지는 따로 확인해야 한다.
- **DD-DB는 ECG가 128Hz라 우리 용도에 약하다.** RR을 7.8ms 단위로밖에 못 재는데 RMSSD·pNN50은 그보다 작은 차이를 다룬다. 참고로 우리 하드웨어의 ADC는 240 SPS(4.2ms)다.
- **UL-DD는 4분마다 KSS로 촘촘하지만** 저자에게 요청해야 받을 수 있고, 공개 설명에는 원시 PPG가 아니라 "심박수"로 적혀 있어 RR을 뽑을 수 있는지 불확실하다. 예선 일정을 생각하면 우선순위가 낮다.
- **PPG와 졸음 라벨이 함께 있는 공개 데이터는 여전히 없다.** ECG로 학습하고 PPG-DaLiA로 차이를 정량화하는 구조 자체는 유지한다.

## MPD-DF (주 학습 데이터)

figshare 28455737, CC BY 4.0. 전체 13.1GB 중 **11.9GB가 32채널 뇌파**라 받지 않는다. 우리가 받는 건 `*_PSG.edf`(50개, 1.18GB)와 `*_Annotation.txt`(50개), 설문 xlsx 하나로 **약 1.2GB**다.

내려받기 주의: figshare API가 알려주는 `ndownloader.figshare.com` 주소는 403을 낸다. `ndownloader.figstatic.com`으로 바꾸면 서명된 S3 주소로 넘겨주고 이어받기(Range)도 된다. API가 파일마다 md5를 주므로 받은 뒤 검증한다.

### 신호 — `MPDDF_raw_NN_PSG.edf`

EDF 헤더를 직접 읽어 확인했다(02번 기준).

| 채널 | 주파수 | 단위 | 범위 |
|---|---|---|---|
| E1-M2, E2-M2 (안전도) | 256 Hz | mV | -1 ~ 1 |
| **ECG** | **1024 Hz** | mV | -2.5 ~ 2.5 |
| Thor (호흡) | 32 Hz | V | -1 ~ 1 |

1초짜리 레코드 7,210개 = **120.2분**. 우리가 쓰는 건 ECG 하나다. AdVitam(1000Hz)과 거의 같은 조건이라 RR 추출 코드를 그대로 쓸 수 있다.

### 라벨 — `MPDDF_raw_NN_Annotation.txt`

`시각,에폭번호,레벨` 세 열이고, **에폭마다 한 줄이 아니라 상태가 바뀌는 지점만** 적혀 있다.

```
14:21:43,1,0     ← 에폭 1부터 레벨 0(각성)
14:33:13,24,1    ← 에폭 24부터 레벨 1(피로1)
14:33:43,25,0    ← 에폭 25부터 다시 각성
```

에폭은 **30초** 단위다(14:21:43→14:33:13이 690초, 에폭 1→24로 23칸 = 690/30). 다음 전이 전까지 같은 레벨이 유지되므로, 전개하면 30초 해상도의 라벨 배열이 된다.

02번 피험자는 전이 51개, 레벨 0/1/2가 등장하며 시간 비율은 각성 65.5%(75분) / 피로1 28.4%(32.5분) / 피로2 6.1%(7분)였다. 상태가 계속 오갈 뿐 한 방향으로 넘어가지 않는다는 점이 AdVitam의 "블록 하나에 값 하나"와 다르다.

### 라벨 50명치 집계 (2026-09-07)

`scripts/inspect_mpd_labels.py` 결과. 에폭 12,531개(104.4시간), 피험자당 240~295 에폭(2시간 전후).

| 라벨 | 에폭 | 시간 | 비율 |
|---|---|---|---|
| 0 각성 | 9,423 | 78.5h | 75.2% |
| 1 피로1 | 2,120 | 17.7h | 16.9% |
| 2 피로2 | 661 | 5.5h | 5.3% |
| 3 N1 | 50 | 0.4h | 0.4% |
| 4 N2 | 10 | 0.1h | 0.1% |
| Severe Artifacts | 248 | 2.1h | 2.0% |
| Signal Abnormality | 19 | 0.2h | 0.2% |

**라벨 자리에 숫자가 아니라 품질 표시가 오기도 한다.** `Severe Artifacts`, `Signal Abnormality` 두 종류이고 합쳐서 2.1%다. 이 구간은 학습·평가에서 뺀다. 데이터셋 제작자도 신호가 나쁜 구간은 판정하지 않았다는 뜻이라, 우리가 SQI로 판단을 보류하는 설계의 근거로 쓸 수 있다.

다만 사람에 따라 편중돼 있다. 05번은 240에폭 중 132개(55%), 47번은 250에폭 중 109개(43.6%)가 아티팩트다. 이 둘은 절반이 못 쓰는 데이터라 제외 여부를 따로 판단한다. 나머지 3명은 7.4% 이하다.

남은 구간 기준 이진 비율은 **각성 76.8% : 피로 23.2%**(약 3.3:1)다.

피험자별 피로 비율 분포(50명):

```
 0~ 9% : ####################  20명
10~19% : #######                7명
20~29% : #######                7명
30~39% : ###                    3명
40~49% : ######                 6명
50~59% : ###                    3명
60~69% : ##                     2명
70~79% : #                      1명
90~99% : #                      1명
```

### 2단계에 반영할 것

- **정확도만 보고하면 안 된다.** 전부 "각성"이라 답해도 77%가 나온다. 계획서의 원칙(민감도·커버리지 병기)이 이 데이터에서 실제로 필요하다.
- **불균형 3.3:1 대응이 필요하다.** 클래스 가중치나 판정 임계값 조정을 쓰고, 어떤 방법을 썼는지 성능 보고서에 적는다.
- **피험자 단위 분할(LOSO)에서 특이 케이스가 있다.** 42·49번은 피로 구간이 0이라 그 폴드에서는 민감도를 계산할 수 없고, 22번은 각성 구간이 아예 없어 특이도를 계산할 수 없다. 폴드별 지표를 단순 평균하지 말고, 계산 불가한 폴드는 제외하거나 전체를 모아서(pooled) 계산하는 방침을 정한다.
- **5단계 분류는 학습하지 않는다.** N1·N2가 합쳐 60에폭(0.5시간)뿐이라 학습이 불가능하다. 계획대로 이진(각성 vs 피로1 이상)으로 묶는다.

### AdVitam과 비교했을 때

- 장점: 라벨이 30초 단위라 윈도우마다 정답이 붙는다. 60초 윈도우 계획과 맞는다.
- 단점 1: 라벨이 **뇌파 판독 기준**이라 KSS 자기보고와 같은 것을 재는지 확인이 필요하다.
- 단점 2: 클래스 불균형이 있다(02번 기준 각성 65% : 피로 35%). 피험자마다 다를 수 있으니 전체를 펼쳐 확인해야 한다.
- 단점 3: 수면부족을 실험적으로 조작하지 않았다. AdVitam은 절반을 6시간 미만으로 재우고 온 설계라 "수면부족 상태의 생체신호"라는 근거가 더 명확하다.

### 결정 (2026-09-07)

**MPD-DF로 학습하고 AdVitam으로 외부 검증한다.** 계획서의 데이터 역할을 이에 맞춰 고쳤다.

- 학습·모델 확정: MPD-DF. 라벨이 30초 단위라 60초 윈도우마다 정답이 붙고, 피험자 단위 분할로 평가한다.
- 외부 검증: AdVitam. **라벨을 새로 매기지 않는다.** MPD-DF로 확정한 모델을 그대로 적용해 30초 판정을 30분 구간 단위로 집계하고, 원래 있던 라벨과 대조한다. 우리 판정을 정답 단위에 맞춰 뭉치는 것이지 정답을 쪼개는 게 아니다. 모델이 만든 라벨로 모델을 채점하면 아무것도 증명되지 않는다.
  - 수면부족 조(32명)와 정상 수면 조(31명)의 졸림 판정 비율이 갈리는가
  - 같은 사람 안에서 블록이 진행될수록 졸림 비율이 오르는가
  - PVT 반응시간이 느려진 5분 구간에 졸림 판정이 몰리는가
- 두 검증은 강약이 아니라 **종류가 다르다.** MPD-DF는 시점 정확도(언제 졸렸는지)를, AdVitam은 일반화(장비·인구·주행 방식이 달라도 되는지)를 본다.
- AdVitam을 남겨두는 이유: 장비·인구·주행 방식이 전부 다르고, **수면부족을 실험적으로 조작한 유일한 데이터**이며, 자율주행(L3) 감시 상황이라 우리 제품이 겨냥한 시나리오와 같다.

**판정 주기와 라벨 간격은 별개다.** 칩은 60초 창을 30초마다 갱신해 판정한다. 30분은 AdVitam 연구팀이 참가자에게 물어본 간격일 뿐 우리 판정 주기가 아니다.
