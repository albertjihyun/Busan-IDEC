## 2.2 설계 목표 및 요구 사항

2.1.3에서 정의한 문제를 풀기 위해, 본 절에서는 설계 목표를 정하고 이를 설계가 지켜야 할 요구 사항과 정량 사양으로 구체화한다.

### 2.2.1 설계 목표

2.1.2에서 보았듯 PPG는 조명과 조향에 무관하게 행동 이전의 변화를 측정할 수 있어, 기존 감시 방식이 비는 조건과 시점을 함께 메운다. 그러나 PPG에 나타나는 변화는 작아 단독으로는 졸음 검출에 부족할 수 있으며, 이 때문에 PPG는 다른 방법과 결합하는 보조 지표로 주로 쓰인다[46]. 본 과제는 이를 보완하기 위해, 졸음이 고개 떨굼이라는 명백한 행동으로 드러나는 순간을 IMU(관성 측정 장치)로 항상 함께 감시한다[17]. 심박은 이르지만 약한 신호이고 고개 떨굼은 늦지만 명백한 신호로, 두 채널은 서로의 약점을 메운다. IMU 역시 조명·착용물·조향과 무관하므로 PPG가 채운 조건을 해치지 않는다.

이를 종합하여 본 과제의 목표를, 이마에서 측정한 PPG와 IMU 신호로 운전 중 각성도 저하를 감지하고 센서 읽기부터 경보 송신까지 전 경로를 범용 프로세서 없이 칩 안에서 처리하는 졸음 감지 SoC의 설계·검증으로 정하였다. 이 목표는 세 갈래로 나뉜다. 감지 측면에서는 심박의 개인 기준선 대비 변화로 각성도 저하를 판정하고 고개 떨굼을 상시 감시한다. 구현 측면에서는 판정을 기기 안에서 끝내고 외부로는 경보만 내보낸다. 검증 측면에서는 공개 실측 데이터로 사람 단위 성능을 확인하고, 하드웨어가 기준 모델과 같게 동작함을 보인다.

### 2.2.2 요구 사항

목표를 이루기 위해 설계가 만족해야 할 요구를 2.1의 분석에서 도출하였다. 각 요구의 충족 여부는 3.6에서 종합한다.

| 구분 | 번호 | 요구 | 도출 근거 | 확인 |
|---|---|---|---|---|
| 감지 | R1 | 차량 거동(조향·차선)과 무관하게 동작한다 | 자율주행 중 차량 거동 기반 감시의 무력화(2.1.2) | 3.1 |
| | R2 | 조명과 착용물(선글라스 등)의 영향을 받지 않는다 | 카메라 DMS의 역광·선글라스 취약성(2.1.2) | 3.2 |
| | R3 | 행동으로 드러나기 전의 신호로 판정한다 | 기존 방식의 뒤늦은 검출 시점(2.1.2) | 3.4 |
| | R4 | 공통 절대 문턱이 아닌 개인 기준선 대비 변화로 판정한다 | 사람마다 다른 평소 심박 수준(2.1.3) | 3.4 |
| | R5 | 고개 떨굼은 심박 판정과 별개로 상시 감시해 즉시 경보한다 | 심박 단독 판정의 한계(2.2.1) | 3.3, 3.4 |
| | R6 | 신뢰할 수 없는 신호로는 판정하지 않는다 | 상황에 맞지 않는 경고는 성가심을 키운다[28] | 3.3, 3.4 |
| 구현 | R7 | 운행 내내 연속으로 판정하고, 입력에서 경보까지의 지연이 정해져 있다 | 예고 없이 요구될 수 있는 제어권 전환(2.1.1) | 3.4, 3.6 |
| | R8 | 판정을 기기 안에서 끝내고 외부로는 경보만 보낸다 | 카메라 DMS를 보완하는 채널이라는 역할(2.1.3) | 3.1, 3.5 |
| 검증 | R9 | 판정 성능은 학습에 쓰지 않은 사람의 실측 데이터로 평가한다 | 사람마다 다른 심박 신호(2.1.3) | 3.4 |
| | R10 | 하드웨어 출력이 소프트웨어 기준 모델과 비트 단위로 일치한다 | 칩 판정이 학습 결과와 같음을 보장 | 3.4, 3.6 |

### 2.2.3 정량 사양

요구 가운데 수치로 정해지는 것은 다음과 같다. 박동을 안정적으로 검출하려면 심박 성분이 일정 진폭 이상이어야 하고, 맥박 간격을 판정에 쓰려면 봉우리 시각의 해상도가 곧 간격 오차가 되므로 충분한 표본화율이 필요하다. 이 두 조건이 아날로그 이득과 ADC 설정을 정한다(3.2).

| 항목 | 값 | 근거 | 관련 요구 |
|---|---|---|---|
| 심박 성분 진폭 | ADC 20 카운트(p-p) 이상 | 봉우리 검출이 박동을 안정적으로 잡는 최소 진폭 | R3 |
| PPG 표본화 | 240 SPS, 12비트 | 맥박 간격 분석에 필요한 시간 해상도[25][26] | R3, R4 |
| 신호 대역 | 0.159–15.9 Hz | 아날로그 프론트엔드 설계(3.2) | R3 |
| 관성 센서 | 6축, 100 Hz | 고개 떨굼 감지 | R5 |
| 경보 출력 | 경보 1회에 1바이트 | 경보만 보내는 출력 | R8 |
| 성능 평가 조건 | 헛경보를 시간당 4회로 고정 | 모든 성능을 같은 헛경보 수준에서 비교 | R9 |

2.3에서는 이 요구를 만족시키기 위한 설계 방향을 정한다.

> 확인: 인용 번호는 저장소 목록 기준이다([46]은 새로 추가한 El Sahmarany 2026). 구글 문서에 넣을 때 첫 등장 순서로 다시 매긴다. 2.2가 3.3.4보다 앞이라 [17]과 새 문헌의 번호가 바뀌고, [25][26][28]도 앞당겨진다.

> 확인: 20 카운트, 신호 대역, 6축 100 Hz는 하드웨어 담당 원고의 값이다. 근거 문장과 3장 절 번호는 담당 원고가 확정되면 맞춘다.

> 확인: 2.3의 결정 표는 아직 옛 기준 ①~⑥을 쓴다. 2.3을 쓸 때 R 번호로 바꾼다.
