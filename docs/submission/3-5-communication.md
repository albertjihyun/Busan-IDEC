## 3.5 통신 블록

> 확인: 통신 담당 절. 통신 모듈 소스와 블록 간 인터페이스 합의로 채운 초안이며 하위 절 구성은 담당이 정한다.

통신 블록은 판정 블록의 경보 펄스를 받아 UART로 한 바이트를 보내고, BLE 모듈(JDY-23)이 그 바이트를 스마트폰으로 전달한다. 칩 밖으로 나가는 정보는 "지금 경보"라는 사실 하나뿐이다.

### 3.5.1 구조와 동작

| 모듈 | 하는 일 |
|---|---|
| `uart_tx_ble` | 경보 펄스를 받아 송신을 시작하고, 송신 중에 온 펄스를 기억한다. BLE 웨이크 핀을 High로 둔다 |
| `uart_tx` | 12 MHz 클럭으로 9600 bps 8N1, LSB 먼저 |

| 항목 | 동작 |
|---|---|
| 송신 | 경보 펄스를 받으면 다음 클럭에 `0x01` 한 바이트를 보낸다. 펄스가 없으면 아무것도 보내지 않는다 |
| 겹침 | 한 바이트 송신에 약 1.04 ms가 걸린다. 그동안 온 펄스는 대기 플래그에 기억했다가 끝나면 한 바이트 더 보낸다. 플래그를 꺼내는 클럭에 새 펄스가 겹쳐도 다시 기억한다 |
| BLE 웨이크 | 항상 High. JDY-23의 웨이크 핀은 Low가 활성이고, 공장 기본 설정에서는 전원이 들어오면 깨어 있어 잠들기 명령 없이는 잠들지 않는다 |
| 모듈 설정 | 공장 기본(9600 8N1 투명 전송) |
| 스마트폰 | 바이트가 오면 경보음, 안 오면 조용. 반복 간격은 판정 블록이 정한다 |

한 프레임(1.04 ms) 안에 펄스가 셋 이상 오면 둘로 합쳐진다. 경보는 5초 단위 판정과 고개 떨굼에서 나와 그렇게 몰리지 않는다.

### 3.5.2 설계 결정

**펄스를 받아 한 바이트.** 판정 블록이 경보를 상태(졸림인 동안 1)로 내면 통신 블록이 반복 간격과 종료 시점을 따로 판단해야 한다. 펄스로 받으면 통신 블록은 "펄스마다 한 바이트"만 하면 되고, 반복 간격 같은 판정 쪽 정책은 판정 블록 안에 남는다. 앞 버전에 있던 5초 주기 샘플링과 웨이크 제어 상태 기계는 이 결정으로 빠졌다.

**모듈 상시 연결.** 경보 때만 BLE 모듈을 깨워 보내려면 연결이 다시 맺어졌는지 알아야 하는데, 이 보드는 FPGA → 모듈 단방향이라(모듈의 송신·상태 핀 미연결) 알 방법이 없다. 연결 상태의 모듈 전류는 약 1 mA로 광원(약 16 mA)보다 작아 재워서 얻는 이득도 작다. 그래서 상시 연결로 둔다.

### 3.5.3 검증

| 시험 | 결과 |
|---|---|
| 통신 블록 단독 테스트벤치: 펄스 두 개를 1클럭부터 한 프레임 넘게까지 모든 간격으로, 무작위 펄스 1,000개, 송신 중 리셋 | 14/14 통과, 유실 0, 바이트 1,000개. 리셋 시 즉시 정지·플래그 소거, 웨이크 핀 Low 0클럭 |
| 판정 블록과 연결 (50명 판정 벡터) | 경보 3,154개 = 바이트 3,154개, 전부 `0x01`, 프레이밍 오류 0 |
| 시스템 최상위 (3.6) | 경보 5개 = 바이트 5개, 웨이크 핀 항상 High |

자원은 단독 합성(Yosys) LUT 28, FF 23이고, 시스템 최상위에 통합하면 LUT 14다.

> 확인: 스마트폰 쪽(앱 또는 BLE 터미널)에서 바이트를 받아 경보음을 내는 부분을 어떻게 시연·설명할지 통신 담당과 정한다.
