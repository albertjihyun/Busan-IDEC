## 3.3 신호처리 블록

> 확인: 하드웨어 담당 절. 신호처리 패키지의 설계 문서와 RTL 주석으로 채운 초안이며 하위 절 구성은 담당이 정한다.

신호처리 블록은 I2C로 ADC와 IMU를 읽어, PPG에서 심박 간격(RR)을 뽑아 5초마다 60초 창 합으로 누산하고, IMU에서 움직임 크기와 고개 끄덕임을 뽑는다. 곱셈기는 저역 FIR의 시분할 곱셈기 하나뿐이고 나머지는 전부 덧셈·비교·시프트다.

| 모듈 | 하는 일 |
|---|---|
| I2C 마스터, 버스 중재 | 오픈드레인, 클럭 스트레칭, 타임아웃, 버스 멈춤 복구. ADC와 IMU가 버스 하나를 나눠 쓰도록 중재 |
| ADC 읽기 | 적응형 폴링, 설정값 대조, 샘플 누락 검출, 고장 복구 |
| 기저선 제거 | 512점 이동평균 감산, 고역 약 0.35 Hz |
| 저역 FIR | 대칭 132탭, 차단 8 Hz |
| 신호 품질 | 2초 창 진폭, 클리핑, 움직임으로 신호 사용 가능 여부 |
| 봉우리 검출 | 적응 문턱 + 구간 최댓값 탐색 3상태 FSM |
| RR 추출 | 박동 단위 통과/탈락 판정 |
| 누산 | 5초 블록 누산, 60초 창 합 3개 |
| IMU 읽기 | 6축 버스트, 100 Hz |
| IMU 특징 | 움직임 에너지, 자이로 끄덕임 검출 |
| LED 구동 | 점등, 워밍업 7초 |

### 3.3.1 센서 읽기

**적응형 폴링.** ADC 내부 발진기와 FPGA 클럭은 비동기다. 고정 주기로 읽으면 두 주기가 맥놀이를 일으켜 변환 결과가 주기적으로 통째로 빠진다. 2.0 ms 고정 폴링에서 17,803변환 중 117개가 정확히 152샘플마다 빠졌다. 새 샘플을 받으면 3.33 ms 쉬고 헛읽으면 0.33 ms 뒤 다시 읽도록 바꿔 유실을 0으로 만들었다. IMU 버스트(1.44 ms)에 밀려도 다음 변환 전에 읽는다.

**설정값 대조.** MCP3421은 전원이 순간 강하하면 설정이 기본값(PGA 1)으로 돌아가는데, 변환은 정상처럼 계속 나와 신호만 약 6분의 1로 줄어든다. 읽기 트랜잭션의 세 번째 바이트가 설정 레지스터라 추가 트래픽 없이 매 샘플 대조하고, 어긋나면 그 샘플을 버리고 다시 설정한다.

**IMU 읽기.** 장치 식별값(0x67)을 확인한 뒤 가속도·자이로 12바이트를 한 번에 읽는다. 폴링 타이머를 트랜잭션 시작 시점에 리셋해 100 Hz를 지킨다(끝난 뒤부터 세면 실제 주기가 늘어 20%가 빠졌다).

### 3.3.2 필터

| 필터 | 구조 | 특성 | 비용 |
|---|---|---|---|
| 기저선 제거 | 최근 512샘플 이동평균을 가운데 샘플에서 뺌 | 고역 약 0.35 Hz, 가운데 탭으로 위상 정렬 | 곱셈 0, 블록 메모리 1 |
| 저역 FIR | 대칭 132탭, Q1.15 계수, 계수 합 = 1 | 4 Hz +0.02 dB, 8 Hz −6 dB, 12 Hz −60 dB, 60 Hz −81 dB. 군지연 273 ms | 대칭으로 곱셈 66회, 곱셈기 1개 시분할 (샘플당 264클럭, 여유의 5%) |

저역 필터를 IIR이 아닌 선형 위상 FIR로 둔 것은 봉우리 시각이 진폭에 따라 밀리지 않게 하기 위해서다. 모든 봉우리가 같은 시간만큼 늦어지므로 심박 간격에는 영향이 없다. 차단을 8 Hz로 둔 것은 더 세게 거르면 맥파 꼭대기가 뭉개져 봉우리 시각 정밀도가 떨어지기 때문이다.

### 3.3.3 신호 품질

2초 창마다 세 가지를 본다.

| 검사 | 내용 |
|---|---|
| 평탄 | 창 안 진폭이 10 코드 미만이면 미접촉·포화·과주변광 |
| 진폭 점수 | 워밍업 중 잡은 자기 기준 진폭 대비 비율로 5단계 채점. 이득·LED 편차·피부·접촉압 같은 곱셈성 변동이 한 번에 정규화된다 |
| 클리핑·움직임 | ADC 레일에 붙은 샘플 수, IMU 움직임 에너지가 문턱(약 0.16 g 지속)을 넘는지 |

클리핑이나 움직임이 있는 창은 기준 진폭 갱신에서 빼고, 그 구간의 박동은 RR 추출에서 탈락시킨다. 움직임 문턱을 PPG-DaLiA 가슴 가속도 15명에 적용하면 운전 중 1.5%, 걷기 97%가 걸린다.

### 3.3.4 봉우리 검출과 RR 추출

**봉우리 검출.** 문턱을 넘은 뒤 구간 최댓값을 찾아 확정하는 3상태 FSM이다. 국소 최댓값을 바로 잡으면 상승 에지 중간의 잡음에서 먼저 터져 박동마다 시각이 달라진다(정답 대비 −17 ~ +5샘플). 구간 최댓값 탐색으로 바꾼 뒤 오차는 중앙값 +1샘플, 사분위 −1 ~ +2샘플(±8 ms)이다. 문턱은 직전 봉우리가 아니라 따로 관리하는 진폭 추정치의 0.625배다. 진폭 추정치는 오를 때 1/4, 내릴 때 1/16씩 따라가므로 오검출 하나가 문턱을 무너뜨리지 못한다. 불응기는 200 ms, 중복맥 가드는 500 ms이고, 400샘플 넘게 봉우리가 없으면 진폭 추정치를 줄여 큰 아티팩트 뒤에도 스스로 복구한다.

**RR 추출.** 봉우리 사이 샘플 수가 RR이다. 아래 중 하나라도 걸리면 탈락시키고, 탈락한 박동은 누산 합에 넣지 않고 탈락 수로만 센다.

| 탈락 조건 | 기준 |
|---|---|
| 범위 | 72 ≤ RR ≤ 360 샘플 (40~200 bpm) 밖 |
| 급변 | 직전 RR 대비 25% 넘게 변함 |
| 샘플 누락 | 직전 봉우리 뒤 ADC 샘플이 빠짐 |
| 움직임 | IMU 움직임 에너지가 문턱 초과 |
| 신호 불량 | 신호 품질 검사 불통과 |

RR 범위와 급변 기준은 판정 블록 문턱을 학습할 때 쓴 값과 같다. 둘이 다르면 통과하는 박동의 집합이 달라져 학습 성능이 옮겨 오지 않는다.

탈락한 봉우리를 다음 RR의 기준점으로 쓸지는 탈락 이유에 따라 나눈다. 너무 길어서 탈락했으면 박동을 놓친 것이므로 기준점을 옮기고, 너무 짧아서 탈락했으면 가짜 봉우리이므로 기준점을 그대로 둔다. 가짜 봉우리부터 재면 다음 진짜 RR이 짧게 통과해, 60 bpm 자극에서 통과 RR 평균이 73.5 bpm(+22%)으로 치우쳤다. 이 규칙을 넣으면 60.4 bpm이다. 판정은 평균을 쓰므로 이 치우침이 그대로 전달된다.

### 3.3.5 누산

1,200샘플(5초)마다 박동 수, RR 합, 탈락 박동 수의 누산기 한 벌을 닫아 12칸 시프트 레지스터에 넣는다. 60초 창 합은 12개를 매번 더하지 않고 "새 블록을 더하고 가장 오래된 블록을 빼는" 러닝 합으로 만들어 항목당 덧셈 두 개로 끝낸다. RR 값 자체는 저장하지 않는다.

| 출력 | 폭 | 상한 근거 |
|---|---|---|
| `n60` | 8 | 60초 × 240 ÷ 72 = 200 |
| `sum_rr60` | 17 | 통과 RR은 겹치지 않으므로 60초 × 240 + 360 = 14,760 |
| `bad60` | 8, 255 포화 | 탈락 봉우리는 불응기만 상한이라 60초에 300까지 가능 |

탈락 수를 8비트에 그대로 담으면 가장 나쁜 창에서 넘쳐 작은 값으로 보이는 역전이 생긴다(모션 85%에서 265 → 9). 그래서 내부는 12비트로 세고 출력만 255에서 묶는다. 판정 블록에서 255는 항상 나쁜 창이 되어 포화 방향이 판정과 맞는다.

### 3.3.6 IMU 처리와 끄덕임 검출

모든 연산은 시프트와 덧셈이다. 중력은 느린 1차 필터(약 0.25 Hz)로 추정하고, 움직임 에너지는 1초 이동합으로 낸다.

**끄덕임 검출.** 끄덕임은 좌우 축을 중심으로 한 회전이므로 가속도 대신 자이로 피치 각속도를 직접 본다. 4 Hz 저역 뒤 아래로 30°/s가 50 ms 이어지면 하강을 시작한 것으로 보고 각속도를 적분해 각도를 잰다. 0.3~2초 안에 위로 20°/s 복귀하고 하강 중 최대 각도가 25°를 넘으면 끄덕임 펄스를, 2초 안에 복귀가 없으면 "떨군 채 유지" 상태를 낸다. 각도는 복귀 순간 값이 아니라 하강 중 최댓값으로 판정한다(복귀 순간 값으로 보면 끄덕임 3회를 0회로 놓쳤다). 25°는 계기판·미러를 흘끗 보는 동작과 가르기 위한 값이다(10°로는 구분되지 않았다).

**자이로 부호 자동 판별.** 헤드밴드를 좌우 어느 쪽으로 쓰느냐에 따라 피치 부호가 뒤집힌다. 착용 뒤 고개 움직임에서 부호를 스스로 판별하고, 확정되면 부호 확정 신호를 올린다. 판정 블록은 확정 전의 끄덕임 결과를 쓰지 않는다(3.4.4).

### 3.3.7 검증

**골든 모델 대조.** 파이썬 골든 모델과 RTL을 비트 단위로 대조했다.

| 시험 | 결과 |
|---|---|
| 전체 체인 (합성 PPG 60 bpm, 17,803샘플) | ADC 손실 0, 봉우리 124, RR 123, 5초 창 14. RR·창 출력 불일치 0. 통과 RR 평균 60.40 bpm |
| 실제 I2C 코어로 전체 체인 (4,200샘플) | 골든과 비트 단위 일치, I2C 트랜잭션 4,916회, 샘플 손실 0 |
| I2C 코어 (와이어 레벨) | 11/11 |
| 고장·중재 (NACK, 변환 누락, 버스 멈춤, 중재, 워치독) | 19/19 |
| IMU 경로 (와이어 레벨) | 17/17. 끄덕임 4회 검출, 떨군 채 유지 1회, 흘끗 보기 14°·얕게 숙임 12°는 무반응, 부호 자동 판별 |
| IMU 읽기 NACK 처리 | 6/6 |
| 탈락 수 포화 | 4/4 |
| LED 구동 | 8/8 |

**실측 신호 재생.** 합성 자극은 골든과 RTL의 등가 확인용이고, 정확도는 공개 실측 기록을 재생해 독립 알고리즘의 박동 위치와 대조했다.

| 기록 | 조건 | 결과 |
|---|---|---|
| PhysioNet 손가락 PPG, 앞 120초 | 깨끗한 구간 | 박동 일치 93.9%, 심박 오차 2.8%, 잔여 지터 11.2 ms, 이중 검출 0 |
| 같은 기록 480초 | 접촉 교란 구간 포함 | 일치 80.0%, 심박 오차 6.2%. 340~353초 교란 구간에서 무너짐(3.8) |
| 이마 PPG + IMU (mhealth24), 240초 구간 | 안정 / 강한 중복맥 / 큰 움직임 / 저진폭 | 30초 심박 오차 0.79 / 5.54 / 14.70 / 2.35 bpm |

이마 기록에서 PPG 극성을 반전하지 않는 쪽을 골랐다. 안정 구간의 심박 오차가 6.84 bpm에서 0.79 bpm으로, RR 탈락률이 26.2%에서 6.3%로 줄었다. 반전하면 중복맥이 주봉우리와 같은 쪽에 놓여 이중 검출을 일으킨다.

> 확인: 실측 기록 두 개의 정확한 출처(PhysioNet 레코드 번호, mhealth24 데이터셋 인용)를 참고문헌에 넣어야 한다.

### 3.3.8 설계 중 잡은 문제

시뮬레이션으로 증상을 재현한 뒤 고친 것들이다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 75박 신호에서 봉우리 109개 | 문턱을 직전 봉우리의 비율로 두면 오검출이 문턱을 끌어내려 바닥까지 무너짐 | 진폭 추정치를 따로 두고 느리게 내림 |
| 17,803변환 중 117개 규칙적 유실 | 고정 주기 폴링과 ADC 발진기의 맥놀이 | 적응형 폴링 |
| IMU 샘플 20% 유실 | 폴링 타이머를 트랜잭션 끝에서 다시 셈 | 트랜잭션 시작에서 리셋 |
| 끄덕임 3회를 0회로 검출 | 복귀 순간의 적분값으로 각도 판정 | 하강 중 최대 각도로 판정 |
| 탈락 뒤 기준값이 나쁜 값에 고정되어 72개 중 71개 탈락 | 대체 기준값이 기동 아티팩트로 시작 | 느슨한 대체 기준(±50%)과 연속 3회 탈락 시 재시작 |
| 신호 품질이 항상 0 | 부호 있는 값과 없는 값을 비교해 비교 전체가 부호 없는 값으로 승격 | 양변을 부호 있는 상수로 명시 |
