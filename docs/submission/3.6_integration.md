## 3.6 통합 검증 및 구현 결과

### 3.6.1 시스템 통합

앞서 네 블록을 각각 설계하고 블록 단위로 검증하였다. 이 절에서는 칩 내부의 세 블록을 하나의 최상위 설계로 통합해 센서 읽기부터 경보 송신까지 이어서 동작하는지 확인하고, 그 결과를 설계 기준에 비추어 정리한다.

신호처리·판정·통신 세 블록은 최상위 모듈에서 서로 연결만 하였고, 통합을 위해 새로 더한 로직은 파워온 리셋 하나다. 이 회로는 별도의 리셋 입력 없이 FPGA 구성이 끝난 직후 15클럭 동안 리셋을 건다. 모든 블록이 12 MHz 단일 클럭과 이 리셋을 공유하며, 블록마다 리셋 방식(비동기·동기)은 다르지만 리셋이 클럭에 동기되어 풀리므로 타이밍 문제가 생기지 않는다. 외부 핀은 클럭, I²C의 SCL·SDA, LED 구동, BLE 모듈로 가는 UART 송신과 BLE_WAKE의 여섯 개다. 신호처리 블록의 디버그·상태 출력은 칩 밖으로 내지 않으므로 합성 과정에서 제거된다.

### 3.6.2 칩 전체 시험

ADC(MCP3421)와 IMU(ICM-42670-P)를 I²C 신호선 수준에서 동작하는 슬레이브 모델로 만들어 같은 버스에 연결하고, 모의 PPG 파형(60 bpm)과 고개 끄덕임 4회·떨군 채 유지 1회를 담은 IMU 자극 40초를 넣어 통합한 칩을 시험하였다. 시뮬레이션 시간을 줄이기 위해 시스템 클럭은 2.4 MHz로 낮추었으나, 두 센서가 버스를 나눠 쓰는 타이밍이 실제와 같도록 I²C는 실제 속도인 100 kHz로 두었고 센서 읽기 타이머도 실제 시간을 유지하게 하였다. 시험 항목 7개는 표 19와 같이 모두 통과하였다.

| 항목 | 결과 |
|---|---|
| 파워온 리셋 | 리셋 해제 뒤 세 블록 정상 시작 |
| ADC·IMU 버스 공유 | ADC 변환 9,600회 중 손실 0, IMU 4,000샘플 수신 |
| 신호처리 → 판정 | 5초 창 8개 전달 |
| 고개 떨굼 전달 | 끄덕임 4회·떨군 채 유지 1회 전달, 부호 확정(14.45초) 전 끄덕임 1회는 경보에서 제외 |
| 기준선 확정 전 심박 판정 | 심박 경보 0 (기준선 확정에 최소 3분 필요) |
| 경보 → UART | 경보 5개(끄덕임 3, 떨군 채 유지 1, 가속도 자세 규칙 1) → 0x01 5바이트, 프레이밍 오류 0 |
| BLE_WAKE | 시험 내내 High |

*표 19. 칩 전체 시험 결과 (I²C 100 kHz, 40초)*

### 3.6.3 구현 결과

칩 전체를 Cmod A7-35T의 FPGA에 배치·배선한 결과는 표 20과 같다.

| 항목 | 결과 |
|---|---|
| LUT | 3,634 (17.5%): 신호처리 3,413, 판정 207, 통신·리셋 14 |
| FF | 3,656 (8.8%) |
| DSP | 4: 저역 FIR 1, 판정식 곱셈 3 |
| 블록 메모리 | 1 (RAMB18 2개): 필터 지연선 |
| 타이밍 | WNS 54.8 ns (주기 83.3 ns), 위반 경로 0 |
| DRC | 에러 0 |
| 게이트 환산 (Yosys) | NAND2 약 5.5만 개, 메모리 약 14 kbit |

*표 20. 칩 전체 구현 결과 (Vivado 2026.1, xc7a35tcpg236-1, 12 MHz, 배치·배선)*

칩은 FPGA LUT의 17.5%를 쓰고, 클럭 주기의 3분의 2가량이 타이밍 여유로 남는다. 이 가운데 판단을 맡는 판정 블록은 칩 전체 LUT의 약 6%다. 각 블록 절에서 제시한 자원은 블록을 단독으로 합성한 값으로, 통합하면 쓰이지 않는 출력의 로직이 빠지고 블록 경계를 넘는 최적화가 적용되어 줄어든다(판정 블록 LUT 305개 → 207개).

앞서 세운 설계 기준별로 목표와 결과를 정리하면 표 21과 같다.

| 기준 | 목표 | 결과 | 확인 방법 |

*표 21. 설계 기준 대비 결과*

판정 성능은 합격선을 두지 않고 평가 조건만 정하였으므로 표와 따로 적는다. 처음 보는 사람에 대해 헛경보 시간당 4회에서 구간 민감도는 0.413, 피로 2단계 이상 구간은 0.633이다. 칩이 실제로 내보내는 경보는 50명에서 구간 민감도 0.406, 피로 2단계 이상 구간 0.600, 헛경보 시간당 4.36회다.

이처럼 세 블록은 하나의 칩으로 센서 읽기부터 경보 1바이트 송신까지 동작하며, 설계 기준의 목표를 모두 충족하였다. 다만 이 결과는 시뮬레이션, 신호 예산 계산, FPGA 합성, 공개 데이터, 모듈 단위 실물 시험으로 얻은 것으로, 센서 보드와 FPGA를 결합한 실측은 포함하지 않는다.

> 확인: 전력 추정(약 74 mW, 대부분 FPGA 정적 전력)은 설계를 평가하는 값이 아니라서 넣지 않았다(9/30 사용자 결정). 필요하면 3.7 한계에 한 줄로.

> 확인: 하드웨어 원고 3.3.1의 "외부 신호 일곱 개(rst_n 포함)"는 시스템 최상위 기준으로 여섯 개(파워온 리셋)다. 담당에게 알릴 것. 3.7 팀원 문단의 "LUT 17.1%, DSP 1개"는 신호처리 블록 단독 값이라 3.7 정리 때 맞춘다.

> 확인: 실측 신호 재생(WildPPG 1명, 30분, 박동 61% 탈락·창 91% 보류·심박 경보 0) 문단은 원본 로그가 없어 뺐다(9/30 사용자 결정). 기준 ④는 판정 블록 대조로 충분하다.
