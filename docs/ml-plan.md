# ML 파트 구현 계획

담당: 유지현 | 프로젝트: PPG 기반 온디바이스 졸음 감지 SoC (팀 쿵쿵딱)

---

## 목표

PPG에서 추출한 심박 간격(RR) 특징으로 각성도 저하를 판정하는 모델을 만들고, 하드웨어(FPGA)에 이식 가능한 형태로 확정한다. IMU는 규칙 기반으로 결합한다.

## 문제 정의와 평가 지표 (2026-09-12 확정)

- **잡는 것은 "각성도가 떨어지고 있는 상태"다.** 이미 잠든 상태(N1·N2)는 학습 데이터가 60에폭뿐이라 대상이 아니다. MPD-DF의 피로1 구간 중 79.8%는 더 깊어지지 않고 각성으로 돌아가므로(`data-notes.md` 사건 통계), "졸음을 예측한다"가 아니라 "각성도 저하를 실시간 감지한다"고 쓴다. 실제로 깊어진 90건은 따로 추적해 "더 나빠지기 전에 잡았는가"를 본다.
- **놓침 방지를 우선한다.** 주 지표는 사건 단위 민감도(445건 중 몇 건에서 한 번이라도 경보했는가), 짝 지표는 시간당 헛경보 횟수. 형태는 "헛경보 N회/시간 이하를 지키며 민감도 최대". N은 5단계에서 정한다. 정확도는 전부 각성이라 찍어도 76.8%라 단독으로 쓰지 않는다.
- **이진화는 0 대 1 이상.** 피로1부터 양성.
- **창 30초(60초와 비교), 갱신 5초, 채점 30초.** 창은 HRV 계산에 박동 수십 개가 필요해서 30초가 하한. 갱신을 5초로 하면 실제 기기에서 창 경계가 사건과 어긋나는 문제가 없어지고 회로 비용은 5초 블록 누산기 12벌뿐(2026-09-14). 채점은 라벨이 30초 단위라 30초 시점의 판정만 본다. 사건 단위로는 사건 구간 안에 경보가 한 번이라도 켜졌는지. 고개 떨굼 같은 초 단위 사건은 IMU가 즉시 처리한다.
- **연속 N회 경보 규칙은 쓰지 않는다.** 30초짜리 사건이 23%라 놓침이 커진다. 헛경보는 모델과 임계값으로 줄인다.
- **모델 입력은 파형에서 나온 것만.** 뇌파·안구·호흡·수면시간·피험자 번호·경과 시간은 입력 금지. 경과 시간은 "초반 N분을 기준선 구간으로 삼는다" 같은 절차에만 쓴다.

## 결과물

1. 학습된 모델의 파라미터 (하드웨어 팀에 전달할 임계값/가중치, 고정소수점 변환본)
2. 특징 추출 절차 명세 (하드웨어 팀이 Verilog로 동일하게 구현할 수 있도록)
3. 성능 보고서 (모델별 정확도·크기 비교, 커버리지, 윈도우 길이별 결과)
4. 결합 규칙 명세 (PPG 판정 + IMU 규칙 합치는 로직)

## 사용 데이터

> 2026-09-07 수정. 처음에는 AdVitam을 주 학습으로 잡았으나, 실제 파일을 열어 라벨 간격을 확인한 뒤 MPD-DF와 역할을 바꿨다. 근거는 `data-notes.md` 참조.

| 데이터셋 | 용도 | 라벨 간격 | 내용 |
|---|---|---|---|
| **MPD-DF** (figshare) | **주 학습** | **30초** | 수동 운전 2시간, ECG 1024Hz, 의사가 뇌파로 판정한 피로 5단계, 50명 |
| **AdVitam** Exp4 (Zenodo) | **외부 검증** | 30분 (+PVT 5분) | 자율주행 L3 감시, ECG 1000Hz, KSS 자기보고, 수면부족 조작, 63명 |
| **PPG-DaLiA** (UCI) | ECG↔PPG 검증 | 졸음 라벨 없음 | 손목 PPG + 가슴 ECG + 가속도 동시 기록, 운전 활동 포함, 15명 |
| ~~DD-DB (Dryad)~~ | 제외 | 이벤트 | ECG가 128Hz라 RR 분해능이 7.8ms. RMSSD·pNN50에 오차가 크다 |

전부 ECG 기반. PPG + 졸음 라벨이 함께 있는 공개 데이터는 존재하지 않으므로, RR 간격이라는 공통 표현으로 ECG에서 학습하고 PPG-DaLiA로 ECG↔PPG 차이를 정량화한다.

**두 데이터의 역할이 다르다.** MPD-DF는 라벨이 30초 단위라 "언제 졸렸는지"를 학습하고 평가할 수 있다. AdVitam은 라벨이 성겨서 시점 평가는 못 하지만, 장비·인구·주행 방식이 전부 다르고 **수면부족을 실험적으로 조작한 유일한 데이터**라 일반화 검증에 쓴다. 라벨 정의도 다르다(뇌파 판독 vs 자기보고).

## 완성 기준과 일정 (2026-09-10 확정)

**ML 파트는 9/19 밤까지 완료한다(2026-09-14 팀 합의).** 피크 검출·RR·누산 Verilog는 하드웨어 팀이 짜고 ML은 규칙과 테스트 벡터를 넘긴다. 추론 Verilog는 ML이 짠다. 인계 내용과 날짜는 [datapath-request.md](./datapath-request.md). FPGA 보드와 PCB는 없이 진행한다. 보드 없이 "완성"이 무엇인지, 경계 신호·비트 폭·검증 흐름·20일 일정은 [hw-design.md](./hw-design.md)에 있다. 이에 맞춰 아래 단계 중 AdVitam 외부 검증, 120초 창, LF/HF는 9/30 범위에서 뺀다. 창 30초와 60초 비교는 2단계에 포함한다. PCB는 제작하지 않으므로 보드 실측·실보드 대조·IMU 착용 검증도 후속 과제다. 발표(10/29) 전 여유가 있으면 넣는다.

## 작업 순서

### 0단계. 환경 준비
- 데이터셋 다운로드 (AdVitam, PPG-DaLiA 먼저)
- 파이썬 환경: numpy, pandas, scipy, scikit-learn, neurokit2 (또는 heartpy), matplotlib
- 데이터 포맷 확인 (샘플링 속도, 라벨 형식, 파일 구조)

### 1단계. RR 간격 추출 파이프라인
- ECG/PPG 원본 → 대역통과 필터 → 피크 검출 → RR 간격 배열
- 처음엔 라이브러리(neurokit2)로 결과 확인, 이후 **단순 임계값 방식으로 직접 구현**하여 결과 비교
  - 이유: 하드웨어에 들어가는 건 단순 방식이므로, 라이브러리와 단순 방식의 차이를 알아야 함
- 피험자 1명 파형과 RR 그래프를 눈으로 확인
- SQI 규칙 초안: RR 정상 범위(0.3~1.5초), 직전 대비 급변 시 탈락

### 2단계. 특징 추출
- 판정 주기 30초. 창 길이는 30초와 60초 두 가지를 만들어 3단계에서 비교한다. 60초는 직전 30초와 겹친다
- 특징 후보 15개를 전부 계산한다. 선정 근거와 뺀 것의 이유는 [feature-rationale.md](./feature-rationale.md)
  - 1차 9개: mean NN, median NN, SDNN, RMSSD, SDSD, CVNN, CVSD, SD2, SD1/SD2
  - 파생 6개: mean NN·SDNN·RMSSD 각각의 개인 기준선 대비값과 직전 창 대비 변화량
  - pNN50·pNN20은 표준 문서와 샘플링 연구가 통계적 성질을 이유로 비권장해 제외
- 라벨 붙이기: 30초 창은 에폭과 1:1. 60초 창은 에폭 두 개에 걸치므로 매핑 규칙(둘 중 하나라도 피로면 피로)을 정하고 기록한다. 아티팩트 에폭에 걸친 창은 버린다
- 창 안 유효 박동 수가 기준 미만이면 창을 버린다(기준값은 1단계 SQI 결과로)
- 특징별로 각성 대 피로 분포를 먼저 그려 본다. 문헌의 방향(HR 감소, 변동 증가)이 재현되는지 확인
- 클래스 불균형(3.3:1) 대응 방법 결정
- 특징 표는 `data/processed/features_{30,60}s.csv`로 저장. 여기서부터는 표 기반 ML이다
- **주파수영역(LF/HF)은 제외.** 30초 창에서 계산이 성립하지 않는다(표준 문서 2~5분 요구)

### 3단계. 모델 학습 및 비교
- 후보 모델을 전부 돌려서 비교 (하나로 미리 정하지 않음)
  - 규칙 기반 단일 임계값 (기준선)
  - 결정트리 (깊이·노드 수 제한)
  - 로지스틱 회귀
  - SVM (선형 / RBF)
  - 랜덤포레스트
  - 소형 MLP
- 학습·평가 데이터는 **MPD-DF**. 5단계 라벨은 이진(각성 vs 피로1 이상)으로 묶는다
- 특징 선택도 이 단계에서 한다. 상관 0.95 이상인 쌍 정리 → 모델 중요도와 순열 중요도 → 하나씩 빼며 재평가. **학습 폴드 안에서만 고른다.** 평가용으로 뺀 피험자는 보지 않는다
- **평가는 반드시 피험자 단위 분할 (leave-one-subject-out).** 42·49번은 피로 0, 22번은 각성 0이라 폴드별 평균 금지, 전체를 모아(pooled) 계산한다
- 비교 지표: 사건 단위 민감도(주), 시간당 헛경보(짝), 창 단위 민감도·특이도, 커버리지. 정확도는 참고로만
- 모델별 하드웨어 비용 표기: 파라미터 수, 곱셈 횟수, 메모리. 예산은 FPGA 용량이 아니라 양산 칩 기준으로 스스로 정한다(곱셈기 시분할 1개, 파라미터 4KB, 추론당 곱셈 1만 회, 가중치 8비트·누산 16비트). 예산 밖 모델(원시 신호 1D-CNN 등)도 비교선으로 함께 돌려 "왜 작게 가나"의 근거로 쓴다
- 결과를 민감도·헛경보·비용 표로 정리 → 이게 "왜 이 모델인가"의 근거
- 창 30초와 60초 결과를 나란히 놓고 창 길이를 확정한다

### 4단계. 하드웨어 제약 반영
- 선정 후보의 고정소수점(8~16비트) 변환 후 정확도 재측정
- 트리 계열이면 깊이/노드 수를 줄여가며 정확도-크기 곡선 작성
- 하드웨어 팀과 노드 수·곱셈기 예산 합의 → 그 제약으로 재학습
- 1024 Hz 원본을 240 Hz로 다운샘플한 뒤 같은 특징을 다시 뽑아 차이를 확인한다. 문헌상 오차 1% 미만이지만 우리 파이프라인에서 재확인한다

### 5단계. 검증
- **ECG↔PPG 검증**: PPG-DaLiA에서 같은 시점의 ECG-RR과 PPG-RR 비교, 특징값 차이 정량화
- **게이팅 임계값 설정**: PPG-DaLiA 가속도 크기 구간별 PPG-RR 오차 → "이 이상 움직이면 판단 보류" 기준값
- **외부 검증 (AdVitam, 9/30 완성 범위에서 제외. 발표 전 여유 시)**: MPD-DF로 확정한 모델을 손대지 않고 AdVitam에 적용한다. 라벨을 새로 매기지 않고, 모델의 30초 판정을 30분 구간 단위로 집계해 원래 라벨과 대조한다
  - 수면부족 조(32명)와 정상 수면 조(31명)의 졸림 판정 비율이 갈리는가
  - 같은 사람 안에서 블록이 진행될수록 졸림 비율이 오르는가
  - PVT 반응시간이 느려진 5분 구간에 졸림 판정이 몰리는가
  - 무너지면 원인을 좁힌 뒤 AdVitam 일부로 미세조정하거나 두 데이터를 합쳐 재학습하는 선택지를 검토한다
- **커버리지 측정**: SQI로 버리는 구간 비율 보고
- **헛경보 측정**: PPG-DaLiA에서 시간당 경보 횟수. 운전 구간은 15명 합계 228분뿐이라 앉기·일하기 같은 안정 구간(총 37시간)까지 포함해 재고, 운전이 아닌 구간이라는 점을 밝힌다
- 성능 부족 시: 특징 추가(LF/HF 등), 윈도우 조정, 모델 변경 검토

### 6단계. IMU 결합 규칙 설계
- 고개 떨굼 감지: 참고 논문(MPU6050) 축별 가속도 임계값에서 출발. 실제 칩은 ICM-42670-P이므로 단위·감도 환산
- 결합 규칙:
  1. 고개 떨굼 감지 → 즉시 경보
  2. 고개 떨굼 없음 → PPG 판정이 졸음일 때 경보
  3. 움직임 과다 → PPG 판정 보류
- 착용 녹화 검증은 PCB를 만들지 않으므로 후속 과제. 9/30에는 문헌값 환산과 시뮬레이션 벡터까지

### 7단계. Verilog 구현과 하드웨어 팀 인계
- 재료 5개 → 특징 → 분류기 → IMU 결합 → 판정 구간을 Verilog로 구현한다. 피크 검출·RR·누산은 하드웨어 팀. 설계는 [hw-design.md](./hw-design.md), 인계는 [datapath-request.md](./datapath-request.md)
- 4단계 정수 정답지에서 뽑은 테스트 벡터로 시뮬레이션을 통과시키고, Vivado로 xc7a35t 합성·구현 리포트를 뽑는다
- 확정 모델의 파라미터를 고정소수점으로 변환하여 파일로 전달
- 특징 추출 절차를 수식과 순서로 문서화 (필터 계수, 피크 검출 규칙, 특징 계산식)
- 테스트 벡터 제공: 입력 RR 배열 → 기대 출력, 하드웨어 구현이 파이썬과 일치하는지 확인용
- 실제 보드 데이터와의 대조는 후속 과제(PCB 미제작). 대신 PPG-DaLiA 실파형을 테스트벤치로 재생해 RTL과 파이썬의 비트 일치를 확인한다

## 실험 원칙

- 피험자 단위 분할로만 평가한다. 랜덤 분할은 정확도를 부풀린다.
- 정확도만 보고하지 않는다. 민감도·커버리지·모델 크기를 함께 본다.
- "95% 가능"이라고 쓰지 않는다. "선행 연구 사례가 있고, 우리 조건에서 검증한다"고 쓴다.
- 모델은 처음부터 하나로 정하지 않고 비교 결과로 정한다.
- 하드웨어 비용을 모델 선정 기준에 포함한다.
- 특징은 생리학적 직관이 아니라 조건(공통성·창 길이·샘플링)으로 거르고 데이터로 고른다. 개별 지표의 변화 방향은 미리 주장하지 않는다.
- 커버리지(SQI·IMU 게이팅으로 버리는 구간 비율)를 성능과 함께 보고한다.
- "하드웨어라서 큰 모델 못 돌린다"고 쓰지 않는다. 작게 가는 이유는 데이터 크기·양산 면적·구현 시간이다.
