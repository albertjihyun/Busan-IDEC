# Verilog 구현 설계

담당: 유지현 | 대상: Cmod A7-35T (xc7a35t, 12 MHz) | 작성: 2026-09-10

이 문서는 ML 파트가 Verilog로 구현하는 구간의 설계 근거를 적는다. 어떤 블록을 만들고, 경계에서 무엇을 주고받고, 숫자를 몇 비트로 다루며, 어떻게 검증하는지를 정한다. 피크 검출 규칙과 분류기 파라미터처럼 파이썬 실험이 끝나야 정해지는 값은 "미정"으로 두고 해당 단계에서 채운다.

## 전체 경로에서의 위치

```
MCP3421 (12bit, 240 SPS, I2C)
  → [하드웨어 팀] I2C 마스터 → FIR 대역통과
  → [ML 파트]    SQI → 피크 검출 → RR → 윈도우 누산 → 특징 → 분류기 → IMU 결합
  → [하드웨어 팀] UART TX → 통신 모듈
MPU6050 (I2C) → [하드웨어 팀] I2C 마스터 → [ML 파트] 고개 떨굼 규칙
```

보드는 없다. 완성의 정의는 다음 세 가지다.

1. PPG-DaLiA의 실제 손목 PPG를 테스트벤치로 재생했을 때 RTL 출력이 파이썬 고정소수점 정답지와 비트 단위로 일치한다.
2. Vivado로 xc7a35t를 목표로 합성·구현하여 LUT, FF, DSP, BRAM 사용량과 타이밍 리포트를 뽑는다.
3. 위 자원 숫자와 ML 정확도를 한 표에 놓는다.

## 경계 신호 (하드웨어 팀과 합의할 것, 2026-09-13 회의)

모든 신호는 `clk` 12 MHz 동기, `rst_n` 액티브 로우.

입력 (하드웨어 팀 → ML 블록)

| 신호 | 폭 | 뜻 |
|---|---|---|
| `sample_valid` | 1 | FIR 출력 샘플이 유효한 클럭. 240 Hz로 1클럭 펄스 |
| `sample` | 16 signed | FIR 출력. 12비트 ADC가 필터를 지나 커진 폭을 담는다 |
| `accel_valid` | 1 | IMU 3축이 유효한 클럭 |
| `accel_x`, `accel_y`, `accel_z` | 16 signed 각각 | MPU6050 원시값 |

출력 (ML 블록 → 하드웨어 팀)

| 신호 | 폭 | 뜻 |
|---|---|---|
| `result_valid` | 1 | 30초마다 1클럭 펄스. 아래 값이 갱신됨 |
| `drowsy` | 1 | 최종 졸음 판정 |
| `head_nod` | 1 | 고개 떨굼 감지 (즉시, `result_valid`와 무관하게 갱신) |
| `hold` | 1 | 움직임 과다 또는 신호 품질 미달로 판정 보류 |
| `n_beats` | 8 | 윈도우 안 유효 박동 수 (커버리지 확인용) |
| `feat_*` | 아래 참조 | 특징 4종의 내부 표현. 디버그·UART 전송용 |

이 경계만 지키면 ML 블록은 보드 없이 시뮬레이션만으로 완성할 수 있고, 하드웨어 팀은 ML 블록 자리에 더미를 꽂고 인터페이스를 따로 검증할 수 있다.

## 숫자 표현

단위는 전부 **샘플 수**로 통일한다. 240 SPS이므로 1샘플 = 4.1667 ms. 밀리초로 바꾸는 나눗셈은 칩에서 하지 않고, 파이썬 쪽에서 임계값을 샘플 단위로 미리 변환한다. pNN50의 기준 50 ms는 정확히 12샘플이라 오차가 없다.

| 양 | 범위 근거 | 폭 |
|---|---|---|
| RR (샘플) | 0.3~1.5 s = 72~360 | 10 unsigned |
| 윈도우 박동 수 N | 60 s / 0.3 s = 최대 200 | 8 unsigned |
| ΣRR | 200 × 360 = 72,000 | 17 unsigned |
| ΣRR² | 200 × 360² = 25.9 M | 25 unsigned |
| 연속 차 d = RR[i] − RR[i−1] | ±288 | 10 signed |
| Σd² | 199 × 288² = 16.5 M | 24 unsigned |
| N50 (|d| > 12인 개수) | ≤ 199 | 8 unsigned |

## 제곱근과 나눗셈을 없애는 방법

분류기가 결정트리나 단일 임계값이면 "특징 > 임계값" 비교만 한다. 그러면 특징을 정의대로 계산할 필요 없이, 부등식을 정수 곱셈만 남도록 변형할 수 있다.

| 특징 | 정의 | 칩에서 비교하는 식 |
|---|---|---|
| mean RR > T | ΣRR / N > T | ΣRR > T · N |
| SDNN > T | √(ΣRR²/N − (ΣRR/N)²) > T | N · ΣRR² − (ΣRR)² > T² · N² |
| RMSSD > T | √(Σd² / (N−1)) > T | Σd² > T² · (N−1) |
| pNN50 > p% | 100 · N50 / (N−1) > p | 100 · N50 > p · (N−1) |

SDNN 식의 좌변은 최대 200 × 25.9 M ≈ 5.2 G로 33비트, 우변은 T가 50샘플(208 ms)이라면 2500 × 40,000 = 100 M로 27비트다. 34비트 비교기 하나와 곱셈 세 번이면 된다. 판정은 30초에 한 번이므로 곱셈기를 하나만 두고 여러 클럭에 걸쳐 순차로 계산해도 된다. 임계값 T²은 파이썬이 미리 제곱해서 넘긴다.

로지스틱 회귀를 고르면 특징값 자체가 필요하므로 이 변형이 통하지 않는다. 그 경우 제곱근 회로나 근사가 추가된다. 3단계 모델 비교 표에 이 차이를 비용으로 기록한다.

## 윈도우를 버퍼 없이 만드는 방법

60초 윈도우를 30초마다 갱신하므로, 윈도우 하나는 "직전 30초 절반 + 현재 30초 절반"이다. RR 값을 전부 저장하지 않고 **30초 절반마다 누산기 다섯 개(N, ΣRR, ΣRR², Σd², N50)를 닫아 두었다가 두 절반을 더한다.** 절반 경계를 넘는 연속 차 하나는 직전 절반의 마지막 RR을 한 개만 기억해 처리한다. 이렇게 하면 BRAM이 필요 없고 레지스터 수십 개로 끝난다.

30초는 240 SPS 기준 7,200샘플이라 13비트 카운터로 센다.

## 블록 목록

| 모듈 | 하는 일 | 상태 |
|---|---|---|
| `sqi` | RR이 72~360 범위 밖이거나 직전 대비 급변이면 탈락 표시 | 급변 기준은 1단계에서 확정 |
| `peak_detect` | 필터 출력에서 봉우리 위치를 찾아 1클럭 펄스로 낸다. 불응기 72샘플 | 알고리즘은 1단계에서 확정 |
| `rr_counter` | 봉우리 사이 샘플 수를 센다 | 확정 |
| `window_acc` | 30초 절반 누산기 두 벌과 합산 | 확정 |
| `classifier` | 위 부등식 비교와 트리 순회 | 파라미터는 4단계에서 확정 |
| `imu_rule` | 3축 가속도 임계값으로 고개 떨굼과 움직임 과다 판정 | 임계값은 6단계에서 확정 |
| `combine` | 고개 떨굼 → 즉시 경보, 움직임 과다 → 보류, 아니면 분류기 판정 | 확정 |
| `drowsy_top` | 위를 묶고 경계 신호를 낸다 | 확정 |

## 검증 흐름

1. 4단계에서 고정소수점 파이썬 정답지를 **정수 연산만으로** 짠다. numpy float를 쓰지 않는다. RTL과 한 줄씩 대응돼야 한다.
2. 정답지가 PPG-DaLiA 구간을 처리하면서 입력 샘플, 중간값(피크 위치, RR, 누산기), 최종 출력을 `sim/vectors/`에 텍스트로 떨군다.
3. Verilog 테스트벤치가 `$readmemh`로 입력을 읽어 240 SPS 간격으로 밀어 넣고, 출력을 기대값과 비교해 불일치를 세어 출력한다.
4. 중간값까지 대조하므로 틀리면 어느 블록에서 갈라졌는지 바로 보인다.
