# 데이터패스 요청서 (ML → 하드웨어)

작성: 유지현, 2026-09-14 | 받는 사람: 이준용 | 최종 갱신: 9/18 예정

ML 추론 블록이 하드웨어 데이터패스에서 받아야 하는 것과, 언제 무엇을 추가로 넘길지 적는다. 이 문서의 1~4절은 오늘 확정이고 5절은 날짜별로 채운다.

## 0. 분담

```
ADC(I2C) → [I2C 시퀀서 → FIR → 피크 검출 → RR → 5초 누산] → 재료 5개 → [특징 → 분류 → 판정] → UART
            준용                                                        지현
IMU(I2C) → [I2C 시퀀서] → 3축 가속도 ────────────────────────────→ [IMU 규칙 → 결합] ─┘
```

- 준용: I2C, FIR, 피크 검출, RR 카운터, 5초 블록 누산기. 피크 검출 **규칙**은 지현이 9/15에 준다.
- 지현: 재료 5개를 받아 특징 계산, 분류기, IMU 규칙, 결합, 상태 변화 신호. 모델은 9/17에 정해진다.
- UART 송신기와 BLE 웨이크 FSM은 별도 합의(준용 또는 성우).

## 1. 재료 5개 (누산기)

박동이 하나 검출될 때마다 아래 다섯 값을 갱신한다. 단위는 전부 **240 SPS 샘플 수**다. 밀리초로 바꾸지 않는다.

| 이름 | 갱신 | 폭 | 최대값 근거 |
|---|---|---|---|
| `n` | +1 | 8 unsigned | 60초 × 최대 3.3 bps = 200 |
| `sum_rr` | += RR | 17 unsigned | 200 × 360 = 72,000 |
| `sum_rr2` | += RR × RR | 25 unsigned | 200 × 360² = 25.9M |
| `sum_d` | += (RR − RR_prev) | 17 signed | ±199 × 288 |
| `sum_d2` | += (RR − RR_prev)² | 24 unsigned | 199 × 288² = 16.5M |

RR은 직전 봉우리와 이번 봉우리 사이 샘플 수. 10 unsigned (72~360). `RR_prev`는 직전 유효 RR 하나만 보관.

블록의 첫 박동은 `RR_prev`가 없으므로 `sum_d`·`sum_d2`에 더하지 않는다. 단, 블록 경계를 넘는 차분은 버리지 않고 직전 블록의 마지막 RR을 `RR_prev`로 이어서 쓴다.

곱셈은 RR×RR과 d×d 두 번뿐이고 박동마다(약 1초에 한 번) 일어난다. 곱셈기 하나를 순차로 써도 된다.

## 2. 5초 블록과 창

- 240 SPS × 5초 = 1,200샘플마다 누산기 한 벌을 닫아 저장하고 0으로 초기화한다. 11비트 카운터.
- 저장한 벌을 최근 **12개**까지 시프트 레지스터에 보관한다. 각 벌은 위 5개 값이므로 91비트, 12벌이면 1,092비트. BRAM 불필요.
- 창 30초 = 최근 6벌 합, 창 60초 = 최근 12벌 합. 어느 쪽을 쓸지는 9/17에 정해지므로 **둘 다 낼 수 있게** 만든다. 합산은 5초마다 한 번이라 순차 덧셈으로 충분하다.
- 합산 결과의 폭은 12벌 기준으로 위 표와 같다(표의 최대값이 60초 기준).

## 3. 신호 인터페이스

클럭 12 MHz, 리셋 액티브 로우. 이름은 준용 그림의 관례(`o_`, `i_`)를 따른다.

**준용 → 지현**

| 신호 | 폭 | 뜻 |
|---|---|---|
| `o_win_valid` | 1 | 5초마다 1클럭 펄스. 아래 값이 갱신됨 |
| `o_n30`, `o_n60` | 8, 8 | 30초·60초 창의 박동 수 |
| `o_sum_rr30`, `o_sum_rr60` | 17, 17 | 창별 ΣRR |
| `o_sum_rr2_30`, `o_sum_rr2_60` | 25, 25 | 창별 ΣRR² |
| `o_sum_d30`, `o_sum_d60` | 17, 17 signed | 창별 Σd |
| `o_sum_d2_30`, `o_sum_d2_60` | 24, 24 | 창별 Σd² |
| `o_sqi_bad` | 1 | 최근 5초 블록에서 SQI 탈락 박동이 기준 이상 |
| `o_accel_x/y/z` | 16 signed × 3 | IMU 원시값 |
| `o_imu_valid` | 1 | 가속도 갱신 펄스 |

창 길이가 9/17에 하나로 정해지면 다른 쪽 신호는 지운다.

**지현 → UART/BLE 제어**

| 신호 | 폭 | 뜻 |
|---|---|---|
| `drowsy` | 1 | 각성도 저하 판정. 5초마다 갱신 |
| `hold` | 1 | 신호 불량 또는 움직임 과다로 판정 보류 |
| `head_nod` | 1 | 고개 떨굼. 즉시 |
| `changed` | 1 | 위 셋 중 하나라도 바뀐 클럭에 1펄스. UART 전송 트리거 |

## 4. 피크 검출과 SQI (자리만, 9/15에 채움)

준용 블록 안에 들어가는 규칙이다. 파형 사진(8/28 벤치)으로 확인한 것까지만 적는다.

- 박동은 **봉우리**다. 천천히 올라가다 급하게 떨어진다. 하강 직전 꼭대기가 기준점.
- 봉우리 뒤 작은 턱(dicrotic notch)이 있다. 불응기로 걸러야 한다.
- 진폭이 접촉 압력에 따라 245~358 mV로 변한다. 절대 문턱은 쓰지 않는다.

9/15에 넘길 것: 기울기 부호 전환 조건, 하강 확인 조건(몇 샘플 안에 얼마나 떨어져야 하는가), 불응기 샘플 수, 상대 진폭 문턱, RR 정상 범위, 직전 대비 급변 기준, 그리고 이 규칙을 검증할 **파형 → 봉우리 위치 → 재료 5개** 테스트 벡터.

| 날짜 | 지현 → 준용 | 내용 |
|---|---|---|
| 9/14 | 이 문서 | 재료 정의, 블록·창 구조, 신호 이름 |

| 9/17 | 특징 목록 (참고) | 준용 회로는 안 바뀜. 창 길이 확정으로 신호 하나 삭제 |
| 9/18 | 재료 → 판정 벡터 | 재료 5개 입력 → drowsy 기대값. 두 블록을 붙여 끝까지 검증할 때 씀 |
| 9/19 | 추론 모듈 + 테스트벤치 | 지현 Verilog 완성 |

## 6. 확인 사항

- IMU I2C 400 kHz 지원 여부는 데이터시트에서 확인. 안 되면 100 kHz로도 충분하다(ADC 240 Hz + IMU 100 Hz).
- ADC 새 샘플 판정은 설정 바이트의 RDY 비트로. 같은 값을 두 번 넘기지 않는다.
- Cmod A7 클럭은 12 MHz. 400 kHz SCL은 30분주.
