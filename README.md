# PPG 기반 온디바이스 졸음 감지 SoC — ML 파트

2026 부산대 IDEC 반도체설계 경진대회 · 팀 쿵쿵딱 · 담당 유지현(ML)

이마 착용형 PPG 센서로 심박 간격(RR)을 얻고, 그 특징으로 졸음을 판단하는 모델을 만들어 **FPGA에 이식 가능한 형태로 확정**하는 것이 이 저장소의 목표입니다. 학습은 PC에서 오프라인으로 하고, 칩에는 추론만 올라갑니다.

---

## 프로젝트 배경

자율주행은 졸음운전을 없애지 못했고, 오히려 졸음 감시를 자율주행의 전제 조건으로 만들었습니다. 카메라 기반 DMS는 선글라스·야간에 취약하고, 조향 패턴 방식은 자율주행 중에는 작동하지 않습니다. 생리 신호로 졸음의 전조를 보는 경로를 **전용 하드웨어**로 구현하는 것이 팀의 접근입니다.

대회 성격상 승부처는 "새로운 기능"이 아니라 "전용 하드웨어 구현 방식"입니다. 따라서 ML 파트도 정확도만이 아니라 **하드웨어 비용(파라미터 수·곱셈 횟수·메모리)을 모델 선정 기준에 포함**합니다.

| 팀원 | 파트 | 담당 |
|---|---|---|
| 이준용 (팀장) | 하드웨어 | 아날로그 프론트엔드, PCB, Verilog |
| 유지현 | **ML** | 특징 추출, 모델 학습·비교, 고정소수점 변환, 하드웨어 인계 |
| 박성우 | 통신 | UART·폰 연동 모듈 |

---

## 이 저장소의 범위

전체 시스템 경로 중 `<<`로 표시한 구간이 ML 파트이며, 이 저장소가 다루는 범위입니다.

```
PPG 센서(BPW34) → AFE(OPA333) → ADC(MCP3421, 12bit / 240 SPS)
  → [FPGA: Cmod A7-35T]
       FIR 대역통과 필터
       → SQI (신호 품질 검사)                              <<
       → 피크 검출 → RR 간격                               <<
       → 시간영역 HRV 특징 (mean RR, SDNN, RMSSD, pNN50)    <<
       → 분류기 (모델 비교 후 확정, 고정소수점 이식)         <<
       → IMU(MPU6050) 규칙 결합 → 졸음 판정                 <<
  → UART 출력
```

ML 파트는 이 구간을 파이썬으로 먼저 구현·검증하고, 하드웨어 팀이 Verilog로 동일하게 구현할 수 있도록 명세와 파라미터를 넘깁니다. 회로·PCB·Verilog 구현은 이 저장소에 포함하지 않습니다.

## 데이터

| 데이터셋 | 용도 | 내용 |
|---|---|---|
| AdVitam (Zenodo) | 주 학습 | 자율주행 L3 시뮬레이션, 346명 중 실험 4(수면부족 63명), ECG + KSS |
| PPG-DaLiA (UCI) | 검증 | 손목 PPG + 가슴 ECG + 가속도 동시 기록, 운전 활동 포함, 15명 |
| DD-DB (Dryad) | 교차 검증(선택) | 운전 시뮬레이터, ECG + 버튼 이벤트 라벨, 10명 |
| MPD-DF (figshare) | 교차 검증(선택) | 운전 시뮬레이터, ECG + 의사 판정 피로 라벨, 50명 |

PPG와 졸음 라벨이 함께 있는 공개 데이터는 없습니다. 그래서 **RR 간격이라는 공통 표현으로 ECG에서 학습하고, PPG-DaLiA로 ECG↔PPG 차이를 정량화**하는 구조를 택했습니다.

## 작업 순서

상세 계획은 [docs/ml-plan.md](./docs/ml-plan.md)에 있습니다.

0. 환경 준비 — 데이터셋 확보, 포맷 확인
1. RR 간격 추출 — 필터·피크 검출. 라이브러리(neurokit2)와 **하드웨어에 실제로 들어갈 단순 임계값 방식**을 각각 구현해 차이 확인
2. 특징 추출 — 60초 윈도우(30초 겹침), 시간영역 4종. 주파수영역(LF/HF)은 FFT 비용 때문에 1차 제외
3. 모델 비교 — 규칙 기반·결정트리·로지스틱 회귀·SVM·랜덤포레스트·소형 MLP를 전부 돌려 정확도-하드웨어비용 표로 비교
4. 하드웨어 제약 반영 — 고정소수점(8~16bit) 변환 후 재측정, 노드 수·곱셈기 예산 합의 후 재학습
5. 검증 — ECG↔PPG 차이, 움직임 게이팅 임계값, SQI 커버리지, 오탐률
6. IMU 결합 규칙 — 고개 떨굼 임계값과 판정 결합 로직
7. 하드웨어 인계 — 파라미터·명세·테스트 벡터 전달, 실측 로그와 파이썬 결과 대조

## 하드웨어 팀에 넘기는 것

1. 확정 모델의 고정소수점 파라미터 파일
2. 특징 추출 절차 명세 (필터 계수, 피크 검출 규칙, 특징 계산식)
3. 테스트 벡터 — 입력 RR 배열에 대한 기대 출력. Verilog 구현이 파이썬과 일치하는지 확인용
4. IMU 결합 규칙 명세

## 실험 원칙

- **피험자 단위 분할(leave-one-subject-out)로만 평가한다.** 랜덤 분할은 정확도를 부풀린다.
- 정확도만 보고하지 않는다. 민감도(졸음을 놓치지 않는 비율)·커버리지·모델 크기를 함께 본다.
- 모델은 처음부터 하나로 정하지 않고 비교 결과로 정한다.
- 하드웨어 비용을 모델 선정 기준에 포함한다.
- 선행 연구 수치를 우리 성능으로 옮겨 쓰지 않는다. 우리 조건에서 검증한 값만 쓴다.

## 범위와 한계

- PPG는 카메라 기반 DMS를 대체하지 않는다. 취약 조건이 서로 다른 **보완** 관계로 본다.
- 노이즈를 완전히 제거한다고 주장하지 않는다. FIR 필터 → SQI → 모델 강건성의 3단으로 다룬다.
- 정확도는 전제가 아니라 검증 대상이다.
- 구현 범위는 FPGA까지이며, ASIC 수준의 자원 제약은 설계 기준으로만 반영한다.
