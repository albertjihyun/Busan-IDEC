# PPG 기반 온디바이스 졸음 감지 SoC

---

## 1. 프로젝트 개요

**대회**: 2026 부산대 IDEC 반도체설계 경진대회 (예선 서류 마감 9/30, 발표 10/29)
**팀명**: 쿵쿵딱 / **작품명**: PPG 기반 온디바이스 졸음 감지 SoC
**성격**: 아이디어 대회가 아니라 설계 역량 대회. "새로운 기능"이 아니라 "전용 하드웨어 구현 방식"이 승부처.

**한 줄 컨셉**
> 자율주행은 졸음운전을 없애지 못했다. 오히려 졸음 감시를 자율주행의 전제 조건으로 만들었다. 우리는 이 지점에서 문제를 발견했고, 반도체 설계로 답을 찾고자 했다.

**시스템**: 이마(헤어밴드) 착용형 PPG 센서 + IMU → 센싱 이후의 신호 처리·품질 검증·특징 추출·추론 경로 전체가 범용 CPU 없이 FPGA 하드웨어 데이터패스로 동작 → UART로 판정 출력

**타깃**: 기업 납품용 장거리 운전자 (B2B). 이유: 이마 착용은 개인 소비자가 안 하지만 회사 지급 장비면 가능. 대규모 보급 조건으로 초저전력·저단가가 도입 조건이 됨.

**포지셔닝**: 카메라 기반 DMS의 대체가 아니라 보완. 카메라는 선글라스·야간에 취약, 조향 패턴 방식은 자율주행 중 작동 불가. PPG는 생리 신호로 졸음의 전조를 봄.

## 3. 시스템 파이프라인

```
PPG 센서 (BPW34 포토다이오드 + LED)
  → AFE (OPA333 증폭, 2단)
  → ADC (MCP3421, I2C, 12비트 / 240 SPS)
  → [FPGA: Cmod A7-35T]
       FIR 대역통과 필터
       → SQI (진폭 범위 + RR 생리학적 타당성 검사) → 불량 구간 판단 보류
       → 피크 검출 → RR 간격 계산
       → 시간영역 HRV 특징 (mean RR, SDNN, RMSSD, pNN50)
       → 분류기 (ML 파트가 모델 비교 후 결정, 고정소수점 파라미터 이식)
       → IMU(MPU6050) 규칙과 결합
       → 졸음 판정
  → UART 출력 (프로토타입: Cmod USB → 노트북 로그 / 제품: 통신 모듈)
```

학습은 PC에서 오프라인, 칩에는 추론만 존재. UART/USB는 개발·검증용 출력이며 추론에 관여하지 않음.

## 4. 하드웨어 진행 현황 (2026-09-06 기준)

### 완료
- **아날로그 프론트엔드 + ADC 설계 완료** (여름방학 중)
  - LTspice 시뮬레이션: `Draft2.asc` (ppg2.txt 입력 파형으로 20초 과도 해석)
  - EasyEDA 회로도: `Sc_ppg.epro2`, PCB: `ppg_PCB1.epro2`
  - 새 통합 프로토타입: `idec_proto.epro2` (IMU 포함, 9/5 스케마틱 완료, PCB 아트웍 진행 중)
- **실물 브레드보드 측정 완료** (8/28, Tektronix 2시리즈)
  - 심박 82 bpm (1.371 Hz), peak-to-peak 358 mV, dicrotic notch 확인
  - 측정 시 OPA333 사용, 오실로스코프 High Res 모드 적용 (→ FPGA에는 이 필터링이 없으므로 FIR 블록이 대신함)

### 부품 확정
| 블록 | 부품 | 비고 |
|---|---|---|
| 포토다이오드 | BPW34 | |
| LED | KT-0603R(적), KT-0805G(녹) + AO3400A 스위치 | LED_IN으로 제어 |
| 증폭기 | **OPA333** | 시뮬(LTC6241)·회로도(MCP6002)·실물(OPA333)이 달랐음 → OPA333으로 통일하기로 함 |
| ADC | MCP3421A0T-E/CH | I2C 주소 0x68, **12비트 / 240 SPS**로 확정 |
| IMU | MPU6050 | I2C 주소 0x69, 참고 논문과 동일 부품 |
| FPGA | Cmod A7-35T (Artix-7) | 온보드 12 MHz 클럭, USB-UART 내장 |
| 커넥터 | 12핀 헤더 (H1) | FPGA 모듈 연결용 |

### 설계 결정 사항
- FPGA는 칩 직접 실장이 아닌 모듈(Cmod) 연결 방식 — 프로토타입 표준
- 전원은 USB (Cmod 경유). 배터리 구동부는 준용 판단 (DNP 풋프린트 방식 제안됨)
- 햅틱(진동) 제외 — PPG 노이즈 유발
- 센서 위치 이마 확정 — PCB+FPGA 크기(약 2.5×5cm)로 귀 뒤 패치 불가, 신호 품질도 이마가 우수
- 검증 경로: ADC raw 값(I2C 수신) + 칩 최종 판정값을 타임스탬프와 함께 UART로 로그 → ML 파트가 파이썬 결과와 대조

### 진행 중 / 미결
- PCB 아트웍 (idec_proto) — 크기 약 2.5×5cm, 탑/바텀 분할로 축소 검토 중
- 배터리 구동부 포함 여부
- Verilog: I2C 수신 + UART 송신 블록이 첫 작업 (데이터 로거 역할)
- 준용 초기 구상은 1D-CNN + INT8 MAC 연산기였으나, ML 파트의 모델 비교 결과에 따라 확정 예정

## 5. ML ↔ 하드웨어 인터페이스

**ML이 하드웨어 팀에 전달할 것**
1. 확정 모델의 고정소수점 파라미터 파일
2. 특징 추출 절차 명세 (필터 계수, 피크 검출 규칙, 특징 계산식)
3. 테스트 벡터 (입력 RR 배열 → 기대 출력)
4. IMU 결합 규칙 명세

**하드웨어가 ML에 전달할 것**
- I2C로 받은 ADC 값 (12비트, 240 SPS) + 칩 판정값, 타임스탬프 포함, CSV 등 텍스트

**공유 제약**
- 곱셈기·온칩 메모리 최소화 (ASIC 수준 자원 제약을 설계 기준으로)
- 하드웨어 예산(노드 수·곱셈기 수)을 모델 학습 단계의 제약조건으로 걸 것
- 주파수영역 특징(LF/HF)은 FFT 비용 때문에 1차 범위 제외

## 7. 우리가 인정하는 것 (질의응답 방어선)

1. 졸음 감지 기능 자체는 새롭지 않다 — 승부처는 구현 방식
2. "자율주행 때문에 사고 급증" 직접 통계는 없다 — 각성 저하 연구 + EU 규제까지만 주장
3. PPG는 카메라를 대체하지 못한다 — 보완
4. 노이즈를 완벽히 제거한다고 주장하지 않는다 — FIR + SQI + ML 강건성의 3단
5. 정확도는 검증 대상이지 전제가 아니다
6. "왜 전용 하드웨어인가"는 MCU 대비 실측(판단 1회당 에너지·지연)으로 답한다
7. 구현 범위는 FPGA까지 — ASIC 제약은 설계 기준으로만 반영
8. PPG + 졸음 라벨 공개 데이터는 없다 — ECG 기반 학습 + PPG-DaLiA로 차이 정량화
